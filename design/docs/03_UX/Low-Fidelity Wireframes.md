# 18. Low-Fidelity Wireframes

## Overview

Low-fidelity wireframes translate the product strategy into tangible user interfaces.

At this stage, the focus is not visual design. Instead, wireframes explore layout, information hierarchy, navigation, user flows, and interaction patterns.

The objective is to validate user experience before investing in visual styling.

---

# Goals

The wireframing phase aims to:

- Validate user journeys
- Establish page hierarchy
- Reduce cognitive load
- Test navigation patterns
- Explore multiple layout directions
- Define reusable page structures

---

# Wireframing Principles

Every wireframe should prioritize:

- Function before aesthetics
- Content before visuals
- User goals before business goals
- Clarity before decoration
- Simplicity before complexity

```text
↓

Supporting Information

↓

↓

```

# Navigation Validation

During wireframing, validate:

- Can users find their goal quickly?
- Is navigation intuitive?
- Are labels understandable?
- Is hierarchy obvious?
- Is the next step clear?

---

# Layout Validation

Evaluate:

- Visual hierarchy
- Information density
- CTA placement
- Scanability
- Mobile responsiveness

---

# Wireframe Deliverables

The output of this phase includes:

- Desktop wireframes
- Mobile wireframes
- Responsive layouts
- Navigation exploration
- Alternative concepts
- Annotation for interactions

---

# Review Checklist

Each wireframe should answer:

- Does it solve one primary problem?
- Is the hierarchy clear?
- Is the CTA obvious?
- Does it reduce cognitive load?
- Does it align with the user journey?
- Does it follow the design principles?

---

# Expected Outcomes

The low-fidelity wireframing phase should:

- Validate navigation
- Reduce usability risks
- Identify layout improvements
- Align stakeholders
- Prepare for visual design
